Found by looking

三个只有把自己的截图看一遍才看得见的 bug

它们的共同点是不抛异常、不让任何测试变红,只是在屏幕上显示错的东西。 自动化门禁对这一类完全无感 —— 所以截图这一步不是交付物,是检查手段。

没跑过的对话,状态行写着「生成中」

已修
症状
新建对话一打开,输入框上方就挂着一行状态,而这个会话一次消息都没发过。
成因
状态行只看 status,而它的初值恰好是 running。
修法
hasRun(transcript, running) —— 问「跑过没有」而不是「现在什么状态」,没跑过就整行不渲染。

run 收尾了,三颗橙色圆点还亮着

已修
症状
状态行明明写着「已完成」,外层 Tab、内层 Tab、侧边栏会话行上的运行圆点一颗没灭,要关掉整个工作区才消。
成因
「在跑」这件事在代码里是两份状态:圆点读全局的 runIndex,输入框和状态行读会话自己的 activeRunId。摘除索引那一步只写在了启动失败的 catch 分支里 —— 于是只有失败的 run 会被摘掉,正常跑完的都留着。
修法
抽出 settleRun(),把两份一起收,applyEnvelope 和 applyEvents 两条路都走它。
兜住
15 个新用例,每个都同时断言两份,任何一份单独对都算红。

状态行右端一根不知从哪来的短横线

已修
症状
一根 64 × 3px、没有标签、填充几乎为零的横条浮在状态行最右边,看着像渲染残留。
成因
上下文压力条一直画着,只是不变色。用掉 4% 上下文时它就长这样。
修法
过半才出现,逼近上限才变色。一个无标注的 3px 条只有在读数本身值得看的时候才传递信息。

Found by grep

还有一个截图看不出来的:两个写好了、但没人调用的函数

方案 §8 写着「per-session store 懒创建、工作区关闭时销毁」。 两个释放函数都写了,注释也写得很清楚,但全仓 grep 下来 生产代码里一次调用都没有 —— 只有一个测试碰过其中一个。 于是开过的每个工作区、每段转录都留在内存里直到退出应用。

更麻烦的是原来那版释放函数连运行中索引里的条目一起删。 真接上去反而会造出一个更难查的 bug:run 还在主进程好好跑着,渲染层却已经不认识它了, 事件泵按 runId 反查会话查不到,事件被静默丢弃 —— 重新打开工作区, 看到的是一段停在半路、而且再也不会动的转录。

修法是给释放加一道闸:正在跑的会话放不掉,而且判断依据必须是全局索引而不是某个 store 的字段 —— ⌘R 重载之后那个 store 压根还没被创建过,字段是空的,但 run 千真万确活着。 然后让关闭工作区那条路真的调用它。

这四条行为逐个做了变异测试:把修好的地方改回去,四个变异体全部被测试杀掉。 一个改坏了代码还能通过的测试等于没写。

Your call

四件我不该替你定的事

前面那些都有参考图可对,照着做就是了。下面这四件参考图给不出答案 —— 要么是截图里根本没有,要么是抄了会有别的问题。

进行中的对话长什么样,是我编的

29 张参考截图里,没有一张是对话生成到一半的。消息气泡、工具调用节点、 可折叠的「深度思考 N 秒」、子代理的展开节点 —— 这些的排版全是我按协议里的事件类型推的, 不是抄的。这是整个界面里最没有依据的一块,而它恰好是用户看得最久的一块。

建议 如果你手上有生成中的参考截图,给我一张就够了。没有的话我先按现在这版做完, 等真正接上模型、能看到长对话滚起来之后再一起调 —— 那时候判断依据比现在充分得多。

浅色主题现在是编的

方案里写了「深浅两套对等」,但参考截图我这边全是深色的。 theme.css 里那套浅色 token 是我按深色的角色关系反推出来的占位, 没有任何一处是量出来的。它现在能跑、不会瞎,但也仅此而已。

建议 浅色留在占位状态,等到步骤 14 做设置页里的主题切换时一起认真做。 现在投入的话,做完也没有东西可以对照验收。

NextCoWork 得有自己的标

现在 Mark.tsx 里是一个占位的 N 字母字标。参考实现左上角那个 M 是 NewMax 的商标,不能照搬,连改一改都不行。 这是全项目唯一一处我没法自己解决的东西 —— 它需要的是一个决定,不是一段代码。

建议 你给方向(字标 / 图形标 / 一个字),我出三版在真界面里截图对比。 在 22 × 22px 的侧边栏顶端能认出来,是唯一的硬约束。

半透明和整块斜杠面板,做不做

两件都能做,但都不便宜。窗口半透明要开 vibrancy 加透明背景,代价是所有面板底色都得重新验一遍对比度, 而且 Windows 上没有等价效果 —— 会变成一个平台一个样子。 整块斜杠面板牵着 SkillRegistry 和会话模式,那是步骤 12 和 14 的东西。

建议 半透明先不做:它是纯观感,而两套主题的对比度还没验过,现在加等于同时动两个变量。 斜杠面板按计划排到步骤 14,和设置页、命令面板一起做 —— 那时候 Skill 注册表是真的,面板里能列出真东西,而不是一排假条目。
