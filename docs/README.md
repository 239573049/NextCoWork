# 桌面应用架构文档

本目录汇总桌面应用(基于 Electron)的核心交互与通信协议文档,覆盖 **进程间通信**、**本地模型网关** 与 **Agent 请求流转** 三大主题。

---

## 总架构

```
┌──────────────────────────────────────────────────────────────────────┐
│  渲染进程 (Renderer · React 18)                                         │
│    window.newmax.*  —— 纯 IPC 客户端,不做任何模型 HTTP 调用             │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │  contextBridge 安全桥 + Electron IPC
                                 │  invoke / send / on  (见 ipc-protocol.md)
┌───────────────────────────────┴──────────────────────────────────────┐
│  主进程 (Main · Node)                                                   │
│                                                                        │
│   ┌─────────────┐   拉起/复用    ┌────────────────────┐                 │
│   │  调度器      │──────────────▶│  推理引擎子进程       │                 │
│   │ (会话/环境/  │               │ 按 ANTHROPIC_BASE_URL│                 │
│   │  回填/取消)  │◀──────────────│ 发起模型请求          │                 │
│   └─────────────┘   解析流回填    └─────────┬──────────┘                 │
│                                            │ 代理开:127.0.0.1:19836     │
│   ┌────────────────────────────────────────┴──────────┐                │
│   │  本地模型网关 (可选中间层)                            │                │
│   │   /v1/messages · /v1/chat/completions · /v1/responses│               │
│   │   协议归一化 + 密钥托管 + 健康检查 + 故障切换          │                │
│   └────────────────────────────────────────┬──────────┘                │
└────────────────────────────────────────────┼──────────────────────────┘
                                              │ 代理关:直连上游
                                              ▼
                          上游 Provider (MiniMax / Qwen / GLM / Kimi / ...)
```

**三条设计主线**

1. **渲染 ↔ 主进程**:一切经 `contextBridge` 暴露的 `window.newmax.*`,底层是命名空间化的 Electron IPC。渲染进程不持有 Node / 网络 / 凭证能力。
2. **本地模型网关**:主进程内常驻的 HTTP 服务(`127.0.0.1:19836`),把多家上游 Provider 归一化为统一的 OpenAI / Anthropic 兼容协议,并提供健康检查与故障切换。可按开关旁路。
3. **Agent 请求流转**:请求从渲染进程发起意图,由主进程组装环境并拉起推理引擎子进程执行;模型调用经网关(或直连)到上游,流式结果原路回填 UI。

## 关键事实速查

| 项 | 值 / 结论 |
|----|-----------|
| 渲染 ↔ 主进程通道 | `contextBridge` 暴露 `window.newmax.*` + Electron IPC(invoke/send/on) |
| 频道命名 | `模块:动作`,冒号分层 |
| 本地网关地址 | `http://127.0.0.1:19836`(默认端口,动态可变) |
| 网关入站端点 | `POST /v1/messages`、`POST /v1/chat/completions`、`GET /v1/models`、`GET /health` |
| 网关鉴权 | `x-api-key`+`anthropic-version` 或 `Authorization: Bearer` |
| 会话映射 | Base URL 携带 `/s/<sessionId>` |
| Agent 运行位置 | 主进程 spawn 的推理引擎子进程(**非渲染进程**) |
| 渲染进程角色 | 纯 IPC 客户端,不直接调网关或上游 |
| 网关是否必经 | 否,`claudeProxyEnabled/failoverEnabled` 决定经网关或直连 |
| 流式回填 | 上游 SSE → 引擎解析 → `agent:chunk` IPC → UI |
