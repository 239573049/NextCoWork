# 模型提供商密钥：程序加密存储 + 查看按钮 + 旧密钥迁移

## 背景

密钥已存在 SQLite `credentials` 表（同一张表还有 OAuth token、MCP 密钥、搜索 key、平台登录 token），但加密依赖 Electron `safeStorage`（OS 密钥环，Linux 无 keyring 时直接拒绝存储）。本次改为**程序自管 AES-256-GCM**（主密钥 = 数据库目录下 0600 权限密钥文件，用户已确认），并新增**查看密钥**能力（所有凭证类型都可查看，用户已确认）。表结构不变 —— 新格式 blob 自带 magic 前缀，迁移在应用层做。

## 一、新模块 `src/main/secrets/credential-crypto.ts`（纯 node:crypto，零 electron，可直测）

- **blob 格式**：`"NCK1"` (4B magic) + version (1B=1) + nonce (12B) + AES-256-GCM 密文 + tag (16B)。
- `isProgramEncrypted(blob)`：按 magic 判别（旧 safeStorage 行 = 无 magic 的任意字节）。
- `encryptCredentialValue(key, plain)` / `decryptCredentialValue(key, blob)`：错 key / 篡改密文时抛错（GCM tag 校验）。
- `loadOrCreateMasterKey(dir)`：读 `<dir>/credential.key`（32 字节随机，`fs.writeFileSync` mode 0600）；已存在则复用。dir 由调用方传 `databaseDirectory()`（跟随 `--user-data-dir`/恢复流程，与库同目录、可一起备份）。
- `migrateCredentialRows(deps)`：迁移编排，依赖注入（`list` / `put` / `decryptLegacy` / `encrypt`），便于测试：无 magic 的行 → 解密 → 新格式重写；解密失败或已是新格式 → 跳过。幂等（转换过的行带 magic，二次运行零改动）。

## 二、`src/main/host/index.ts` — `electronSecrets()` 重写

- `set`：`encryptCredentialValue(masterKey, value)` 后落库；**删除「无 keyring 拒绝存储」分支**（Linux 问题就此消除）。
- `get`：`isProgramEncrypted` → 程序解密；否则（旧 safeStorage 行，含未来从旧备份恢复的行）→ `safeStorage.decryptString` 兜底。双格式读是长期保留的降级路径，不只服务迁移。
- `available()`：恒 `true`（主密钥文件不可读写时 set/get 自然抛错，走既有错误通道）。
- 同文件导出 `migrateLegacyCredentials()` 胶水：safeStorage + `repo.listCredentials/putCredential` + crypto 接线。

## 三、`src/main/index.ts` — 启动迁移

`whenReady` 回调里 `openDatabase()` → `electronHost()` 之后调用 `migrateLegacyCredentials()`（safeStorage 要求 app ready）。带 `console.` 前缀诊断日志（迁移数 / 跳过数）。safeStorage 不可用且有旧行时跳过该行（读路径兜底），不阻塞启动。

## 四、查看密钥 IPC

- `src/shared/ipc/contract.ts`：新频道 `'provider:revealCredential': { req: { providerId: string }; res: RevealedCredential }` + `CONTRACT_VERSIONS` 条目。注释写明「显式动作才回传明文，禁止用于列表/轮询路径」。
- `src/shared/domain/provider.ts`：新增 `RevealedCredential`（`kind: 'api-key' | 'oauth'`，api-key 回 `apiKey`，oauth 回 `accessToken` + `refreshToken`）。
- `src/main/ipc/provider.ts`：`revealCredential(providerId)` —— `parseCredential(secrets.get(ref))`，null 抛「还没有配置密钥」；按 kind 组装返回。**不拒绝内置供应商**（用户选择所有凭证可查看）。
- `src/main/ipc/index.ts`：注册 handler。
- `src/renderer/src/services/provider.ts`：`revealCredential()` 包装函数。

## 五、界面（ProviderPanel.tsx，OAuth 区也在本文件内）

- **API Key 已配置态**（掩码框）：框内加 Eye/EyeOff（lucide）图标按钮。点击 → `revealCredential` → 明文替换掩码（`break-all` 可选中、去掉宽字距、普通前景色）；再点隐藏。旁边加复制按钮（沿用 `navigator.clipboard?.writeText` 既有写法）。状态收在组件局部 `useState`，不进 store、不缓存，切供应商/进编辑态即清空。
- **内置供应商掩码行**：同一颗眼睛按钮（揭示的是登录 JWT）。
- **OAuth 已登录态**（`ProviderAuthField`）：加「查看 Token」折叠按钮，展开显示 access/refresh 两行 + 各自复制按钮。
- busy 期间禁用；失败按面板既有错误提示路径展示。

## 已知取舍（需要知晓）

1. **回退旧版本**：旧版只认 safeStorage 密文，新格式行在旧版下等于「未配置」，需重填密钥 —— 无法两全，接受。
2. 纯密钥文件方案下，macOS/Windows 的保护强度从「OS 绑定」降为「文件权限」（用户已确认选择）。
3. `provider:export`（密码加密导出）、账户切换（字节级复制）、数据导入回滚等路径经双格式 `get` 全部兼容，无需改动。
