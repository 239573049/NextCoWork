# ncw.bilibili —— 零代码网页应用示例

**这个包里没有一行 JavaScript。** 它存在的意义就是证明这句话:把一个网站带进
NextCoWork,不应该要求作者先学会写 `activate()`、打包一个单文件 ESM、
再让宿主为它常驻一个隐藏进程。

## 它长什么样

```
ncw.bilibili/
├── package.json     ← 全部内容都在这里
└── l10n/
    ├── zh-CN.json
    └── en-US.json
```

装上之后:侧边栏多两条入口(「哔哩哔哩」「动态」),点第一条在工作区里开一个
Tab,点第二条开在右侧工作台。登录态与你自己的浏览器标签**共享**同一个工作区
分区 —— 在浏览器里登录过,这里直接就是登录状态。

## 三个值得注意的地方

1. **`"kind": "webapp"`** —— 没有 `main`,宿主一个进程都不为它起。
   写了 `main` 会被整份拒绝(而不是忽略),因为忽略的话作者会以为自己的代码在跑。

2. **`hostPermissions` 决定它能去哪。** 站内链接在 Tab 里走;点到站外(比如一条
   外链广告)会被拦下来交给系统浏览器,并在顶部说明一句。没有这一条的话,
   「B 站插件」点两下就变成一个不受限的浏览器,而用户在安装界面上看到的域名
   只有 bilibili.com。

3. **`permissions` 是空的。** 网址写死在清单里、用户安装时就看得见,所以不需要
   `tabs.browser` 能力 —— 那条是给**运行期动态**打开地址的插件(`tabs.openBrowser`)
   准备的。

## 装它

扩展页 → 安装插件 → 选这个目录(开发模式支持直接装目录,不必先打成 ZIP)。

## 想在这个基础上加点逻辑?

把 `kind` 去掉(或改成 `"extension"`)、补上 `main`,就可以再贡献命令、工具、
自定义编辑器。`packages/create-nextcowork-plugin` 生成的骨架就是那一套。
